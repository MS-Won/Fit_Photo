# 증명사진 규격 맞춤기: 설계 문서

- 작성일: 2026-10-01
- 상태: 승인됨 (2026-10-01)
- 배경 조사: [docs/research/2026-10-01-market-research.md](../../research/2026-10-01-market-research.md)

## 0. 목표와 원칙

- **목표**: 기관을 고르면 그 기관 규격(픽셀, 실물 크기, 용량, 머리 비율)에 정확히 맞는 증명사진 JPG를 브라우저에서 만들어 준다.
- **차별점**: (1) 한국 기관 규격을 가장 정확하고 깊게 다룸 (공식 출처와 확인 날짜 표기), (2) 기관별 랜딩 페이지로 롱테일 검색 유입, (3) 사진이 서버로 가지 않음, (4) 규격을 한 장의 도해로 보여주는 전문적인 인상.
- **출시 기한**: 착수 후 3~5일 (규격 도해 때문에 +1일 여유 허용). 도해 품질 다듬기로 출시가 밀리면 단순 버전으로 먼저 출시한다.
- **성공 기준 (출시 2~3주 후)**: Search Console 노출·클릭, 다운로드 이벤트 수. 이 숫자를 보고 HWP 변환기로 넘어갈지 판단.

## 1. 전체 구조와 페이지 구성 (승인됨)

### 1.1 사이트 구조

```
/                         사이트 홈 (도구 목록, 지금은 증명사진 하나)
/photo                    증명사진 메인 (기관 선택 + 직접 입력)
/photo/passport           여권
/photo/id-card            주민등록증
/photo/driver-license     운전면허 (온라인 갱신)
/photo/qnet               Q-net
/photo/gosi               공무원 시험 (사이버국가고시센터)
/photo/toeic              토익
/privacy                  개인정보처리방침 (AdSense 승인 필수)
```

나중에 `/hwp`, `/receipt` 도구가 같은 사이트에 추가된다.

### 1.2 기관별 페이지 구성 (위 → 아래)

1. 제목: 예) "여권사진 규격 맞추기: 3.5×4.5cm, 413×531px, 500KB"
2. **규격 도해 (Before → After)**: 섹션 2
3. **도구 본체**: 해당 기관 규격이 미리 설정된 상태
4. 규격 요약표 + 공식 출처 링크 + 확인 날짜
5. 제출 전 체크리스트 (흰 배경, 6개월 이내 촬영 등 기계로 확인 못 하는 조건)
6. FAQ 3~5개 (실제 반려 사유 중심)
7. 광고 자리 2곳 (도구 아래, 본문 중간). 승인 전에는 렌더링하지 않음

### 1.3 데이터

- `src/data/photo-presets.ts` 하나에 기관 6개 규격을 담는다.
- 빌드 시 `generateStaticParams`로 `/photo/[preset]` 페이지와 sitemap을 생성한다.
- 프리셋 타입:

```ts
type PhotoPreset = {
  slug: string;                 // 'passport'
  name: string;                 // '여권'
  org: string;                  // '외교부'
  physicalCm: { w: number; h: number };            // 3.5 × 4.5
  pixels:
    | { mode: 'exact'; w: number; h: number }
    | { mode: 'range'; recommended: { w: number; h: number };
        min?: { w: number; h: number }; max?: { w: number; h: number } };
  format: 'jpg';
  fileSizeKB: { min?: number; max: number };
  head?: {                       // 머리 길이(정수리~턱) 규정이 있을 때만
    minCm: number; maxCm: number;            // 3.2 ~ 3.6
  };                             // 정수리 위 여백은 규정이 없어 "남는 세로 공간의 40%" 권장값으로 계산
  background?: 'white' | 'plain';
  checklist: string[];
  faq: { q: string; a: string }[];
  sources: { label: string; url: string }[];
  verifiedAt: string;            // '2026-10-02' (공식 출처로 확인한 날짜)
};
```

- **규칙**: 공식 출처로 확인하지 못한 값은 넣지 않는다. 확인 못 한 프리셋은 출시 목록에서 뺀다. `sources`가 비었거나 `verifiedAt`이 없으면 테스트가 실패한다.

### 1.4 기술과 배포

- Next.js (App Router) + TypeScript, `output: 'export'` 정적 내보내기
- GitHub → Cloudflare Pages (무료)
- 분석: GA4 (페이지뷰 + `photo_download` 이벤트), Google Search Console + sitemap
- 광고: 출시 후 AdSense 신청 (승인에 수 주가 걸릴 수 있음)

### 1.5 이번 범위에서 제외 (YAGNI)

로그인, 결제, 다국어, 다크모드 토글, 사용자 프리셋 저장, 얼굴 자동 인식, 배경 제거, 인화용 4×6 배치 출력, 홈 화면 대표 도해 갤러리.
단, `/photo`에 "직접 입력(가로·세로 px, 최대 용량)"은 넣는다.

## 2. 규격 도해 (Before → After)

### 2.1 무엇을 보여주나

글머리표 설명 대신 **사진 한 장으로** 변환 과정 전체를 보여준다.

```
┌─────────── BEFORE ───────────┐        ┌──────────── AFTER ────────────┐
│ 원본 사진 (예시 인물)          │        │   ← 3.5cm / 413px →            │
│  ┌ ─ ─ ─ ─ ─ ┐ ← 크롭 영역     │        │  ┬ ───────────── 정수리 선      │
│    (점선)     잘려나가는 부분    │  ──▶   │  │    (얼굴)                   │ ↑
│  └ ─ ─ ─ ─ ─ ┘   반투명 처리     │        │  │ 머리 길이 3.4cm            │ 4.5cm
│                               │        │  │ (허용 3.2~3.6 = 높이 71~80%) │ 531px
│ 3024 × 4032 px                 │        │  ┴ ───────────── 턱 선          │ ↓
│ HEIC · 3.2MB                   │        │ 중앙 세로선, 눈높이 선           │
└───────────────────────────────┘        └───────────────────────────────┘
                     용량 3.2MB → 187KB (−94%) · HEIC → JPG
```

포함 요소:
- Before: 원본 픽셀 크기, 형식, 용량 / 크롭 영역 점선, 잘려나가는 부분 반투명 처리
- After: 가로·세로 치수선 (cm + px), 머리 길이 치수선과 허용 범위 띠, 비율 계산 표시 (예: 3.2/4.5 = 71% ~ 3.6/4.5 = 80%), 정수리 선, 턱 선, 중앙선, 눈높이 선
- 하단: 용량 변화 (−%), 형식 변화
- 머리 규정이 없는 기관(예: 토익)은 머리 치수선 대신 "얼굴이 잘 보이도록 중앙 배치" 가이드만 표시

### 2.2 만드는 방식: 데이터에서 자동 생성하는 SVG

- 포토샵으로 기관별 이미지 6장을 만들지 않는다. **React 컴포넌트 `<SpecDiagram>`가 프리셋 데이터 + 예시 사진 메타데이터를 받아 SVG로 그린다.**
  - 프리셋이 추가되면 도해도 자동 생성 → 롱테일 페이지 확장과 맞음
  - 숫자가 데이터에서 나오므로 규격표와 도해가 서로 어긋날 일이 없음
  - 빌드 시 HTML에 포함되어 선명하고, 검색엔진용 대체 텍스트도 붙일 수 있음
- 예시 사진 메타데이터 (`src/data/sample-photo.ts`): 원본 이미지 경로, 원본 px, 형식, 용량, 그리고 사람이 한 번 직접 찍어 둔 얼굴 좌표 (정수리 y, 턱 y, 눈 y, 얼굴 중심 x).
- 크롭 영역 계산: 기관 규격의 머리 길이 허용 범위 중간값에 맞춰 크롭 박스를 계산 → 도구 본체의 크롭 계산 함수와 **같은 함수**를 재사용.
- After 화면은 원본 이미지의 크롭 영역을 SVG로 잘라 보여준다 (별도 결과 이미지 파일 불필요).
- After 용량은 빌드 시 실제로 인코딩해 측정한 값을 쓴다 (꾸며낸 숫자 금지). 빌드 스크립트 `scripts/build-samples.ts`가 기관별 결과 JPG를 메모리에서 인코딩해 용량을 `src/data/sample-results.json`에 기록.

### 2.3 예시 인물 사진

- 초상권 문제를 피하기 위해 **AI 생성 가상 인물** 또는 상업적 사용이 허락된 사진 1장을 쓴다. 도해에 "예시 인물(가상)" 표기.
- **결정됨 (2026-10-01)**: AI 생성 가상 인물 사용. 사용자가 이미지 생성 도구로 만들고, 구현 계획에 생성 프롬프트(정면, 흰 배경, 어깨 위 상반신, 세로 3:4, 고해상도)를 포함한다. 확보 전에는 실루엣 일러스트로 개발을 진행하고, 사진이 늦어져도 출시를 막지 않는다.

### 2.4 이번 범위 밖

- 홈 화면 대표 도해 갤러리 (같은 컴포넌트를 재사용하므로 나중에 쉽게 추가)
- 사용자 본인 사진으로 만든 결과 도해 (결과 화면에는 치수선만 간단히 표시)

## 3. 도구 화면과 처리 흐름

### 3.1 단계

1. **사진 올리기**: 드래그 앤 드롭, 파일 선택, 모바일 사진첩. JPG/PNG/WEBP/HEIC 지원 (HEIC 변환 라이브러리는 HEIC 파일일 때만 지연 로드). EXIF 회전 정보 반영.
2. **크롭**: 기관 비율로 고정된 크롭 박스 (`react-easy-crop`). 드래그·확대로 맞춤. 겹쳐 보이는 가이드: 정수리 허용 띠, 턱 허용 띠, 중앙 세로선, 눈높이 참고선. 가이드 위치는 프리셋의 머리 길이 범위에서 계산.
3. **내보내기**:
   - 캔버스에 목표 픽셀로 그림 (exact면 그 값, range면 recommended)
   - JPEG 품질을 이진 탐색해 `min ≤ 용량 ≤ max`를 만족하는 가장 높은 품질 선택
   - JFIF 헤더에 DPI 기록 (목표 px ÷ 실물 cm로 계산), 인쇄 시 실물 크기가 맞도록
4. **결과**: 미리보기, 최종 px / KB / cm 표시, 규격 충족 체크 (✓ 픽셀 ✓ 용량 ✓ 형식), 다운로드 (`여권사진_413x531.jpg`), GA4 `photo_download` 이벤트.

### 3.2 모듈 구성 (각각 독립적으로 테스트 가능)

| 모듈 | 책임 | 의존 |
|---|---|---|
| `lib/presets` | 프리셋 타입, 데이터, 검증 | 없음 |
| `lib/crop-math` | 머리 범위 → 가이드선 위치, 얼굴 좌표 → 크롭 박스 계산 | presets |
| `lib/encode` | 캔버스 → JPEG, 용량 맞춤 이진 탐색 (인코더 주입 가능) | 없음 |
| `lib/jfif-dpi` | JPEG 바이트에 DPI 기록 | 없음 |
| `lib/load-image` | 파일 → 이미지 (HEIC 변환, EXIF 회전, 대형 이미지 축소) | heic2any (지연) |
| `components/SpecDiagram` | 규격 도해 SVG | presets, crop-math |
| `components/PhotoTool` | 업로드 → 크롭 → 결과 UI | 위 lib 전부 |

## 4. 오류 처리

| 상황 | 처리 |
|---|---|
| 지원하지 않는 파일 | 안내 문구 + 지원 형식 표시 |
| HEIC 변환 실패 | "아이폰 설정 > 카메라 > 포맷 > 높은 호환성" 안내 |
| 아주 큰 이미지 (> 4000만 화소) | 로드 직후 축소해 메모리 문제 방지 |
| 원본이 목표 픽셀보다 작음 | 경고: "원본 해상도가 낮아 확대됨, 반려될 수 있음" |
| 최고 품질로도 최소 용량 미달 | 경고 + 그래도 다운로드 허용 (공무원 시험 20KB 하한 대비) |
| 최저 품질로도 최대 용량 초과 | 경고 (현실적으로 거의 없음) |
| 브라우저 미지원 (캔버스/Blob) | 최신 브라우저 안내 |

모든 처리가 로컬이라 네트워크 오류는 없다.

## 5. 테스트와 검증

- **단위 테스트 (Vitest)**:
  - 프리셋 검증: 모든 프리셋에 `sources`와 `verifiedAt` 존재, 픽셀 비율이 실물 비율과 ±2% 이내, 머리 범위가 사진 높이 안
  - `crop-math`: 여권 기준 가이드선 위치, 얼굴 좌표 → 크롭 박스
  - `encode`: 가짜 인코더로 이진 탐색이 min/max를 지키는지, 경계 상황
  - `jfif-dpi`: DPI 기록 후 바이트 확인
- **빌드 검증**: `scripts/build-samples.ts`가 기관별 After 이미지를 만들고 규격 충족 여부를 검사, 하나라도 실패하면 빌드 실패
- **수동 QA (출시 전)**: 모바일 Safari·Chrome, 데스크톱 Chrome에서 아이폰 HEIC·안드로이드 JPG로 6개 기관 모두 생성. 가능하면 실제 사이트(Q-net 등) 업로드 화면에서 통과하는지 사용자가 직접 확인
- E2E 자동화는 이번 범위에서 제외
